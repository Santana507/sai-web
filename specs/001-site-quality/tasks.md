# Roadmap de trabajo — BPVDA

Esta es la lista única de trabajo de la spec 001. Las tareas están ordenadas por dependencia y prioridad.

## Estados

- `[x]` Completada con evidencia.
- `[ ]` Pendiente y trabajable.
- `BLOQUEADA` Requiere información o aprobación externa.
- **P0** Imprescindible.
- **P1** Siguiente mejora.
- **P2** Publicación o evolución.

## Fase 0 — Organización documental (P0)

- [x] **T01.** Crear AGENTS.md como contexto operativo principal.
  - Hecho cuando: describe alcance, arquitectura, reglas, flujo y validación.
- [x] **T02.** Crear README.md como índice del proyecto.
  - Hecho cuando: explica estado, estructura, forma de trabajo y comandos.
- [x] **T03.** Crear constitution.md, spec.md, plan.md, clarifications.md y validation.md.
  - Hecho cuando: los documentos describen el mismo alcance.
- [x] **T04.** Ordenar este roadmap.
  - Hecho cuando: cada tarea tiene prioridad, dependencia y Hecho cuando:.

## Fase 1 — Diagnóstico del sitio actual (P0)

- [ ] **T05.** Auditar navegación y enlaces de las ocho áreas.
  - Hecho cuando: existe una lista de enlaces válidos y correcciones necesarias.
- [ ] **T06.** Auditar contenido y datos provisionales.
  - Hecho cuando: cada dato pendiente está identificado para confirmación.
- [ ] **T07.** Auditar accesibilidad.
  - Hecho cuando: se revisan teclado, foco, encabezados, alt, contraste y reduced motion.

## Fase 2 — Mejoras de experiencia (P1)

- [ ] **T08.** Corregir hallazgos responsive.
  - Hecho cuando: no hay desbordamientos, solapamientos ni controles inutilizables en los tamaños objetivo.
- [ ] **T09.** Mejorar las páginas con cambios visuales pequeños y trazables.
  - Hecho cuando: cada cambio conserva contenido, tiene captura o comparación y queda documentado.
- [ ] **T10.** Revisar rendimiento de imágenes y videos.
  - Hecho cuando: los medios tienen formato, tamaño, carga y comportamiento justificados.

## Fase 3 — Publicación y evolución (P2)

- [ ] **T11. BLOQUEADA.** Confirmar datos institucionales y destinatario del formulario.
  - Hecho cuando: BPVDA aprueba los datos definitivos.
- [ ] **T12. BLOQUEADA.** Confirmar hosting y proceso de publicación.
  - Hecho cuando: existe una guía de despliegue y reversión.
- [ ] **T13.** Ejecutar revisión editorial y visual final.
  - Hecho cuando: las ocho áreas tienen aprobación y validación documentada.
- [ ] **T14.** Crear una spec separada si se decide usar CMS o integraciones.
  - Hecho cuando: la decisión tiene alcance, riesgos, plan y criterios propios.

1. Ejecutar T05 y T06.

3. Resolver las decisiones bloqueadas.
4. Tomar una tarea por vez y validar antes de marcarla.
